## ENCRYPTION & SECURITY ARCHITECTURE
====================================

### 1. RSA ASYMMETRIC ENCRYPTION
-------------------------------
**Implementation:** RSA-1024 bit key pairs
**Files:** encrypt.py, public.pem, private.pem
**Library:** `rsa==4.9.1`

**Key Generation Process:**
- RSA key pairs are generated using `rsa.newkeys(1024)`
- Public key saved as "public.pem" in PKCS#1 PEM format
- Private key saved as "private.pem" in PKCS#1 PEM format
- Key size: 1024 bits (suitable for educational purposes)

**Usage in System:**
- Client (ATM) loads public key to encrypt symmetric key
- Server loads private key to decrypt symmetric key
- Establishes secure channel for symmetric key exchange

**Code Example:**
```python
# Key Generation (encrypt.py)
public_key, private_key = rsa.newkeys(1024)
with open("public.pem", "wb") as f:
    f.write(public_key.save_pkcs1("PEM"))

# Client-side encryption (atm.py)
with open("public.pem", "rb") as f:
    public_key = rsa.PublicKey.load_pkcs1(f.read())
encrypted_sym_key = rsa.encrypt(sym_key, public_key)

# Server-side decryption (bank.py)
with open("private.pem", "rb") as f:
    private_key = rsa.PrivateKey.load_pkcs1(f.read())
decrypted_sym_key = rsa.decrypt(encrypted_sym_key, private_key)
```

### 2. SYMMETRIC ENCRYPTION (FERNET)
----------------------------------
**Implementation:** Fernet encryption from cryptography library
**Library:** `cryptography==45.0.2`, `cryptography-fernet==0.1.0`

**Key Generation Process:**
- Fernet symmetric keys generated using `Fernet.generate_key()`
- Alternative: Scrypt-based key derivation from random strings
- Salt-based key strengthening using `scrypt` library

**Usage in System:**
- Encrypts user credentials (username, password) during transmission
- Encrypts transaction data between client and server
- Provides authenticated encryption (confidentiality + integrity)

**Code Example:**
```python
# Key generation
sym_key = Fernet.generate_key()
fernet = Fernet(sym_key)

# Encryption
encrypted_user_id = fernet.encrypt(user_id.encode())
encrypted_password = fernet.encrypt(password.encode())

# Decryption
user_id = fernet.decrypt(recd_data[1]).decode()
password = fernet.decrypt(recd_data[2]).decode()
```

### 3. SCRYPT KEY DERIVATION
---------------------------
**Implementation:** Scrypt-based key strengthening
**Library:** `scrypt==0.8.27`

**Parameters:**
- N=2048 (CPU/memory cost parameter)
- r=8 (block size parameter)
- p=1 (parallelization parameter)
- buflen=32 (derived key length)

**Code Example:**
```python
random_string = ''.join(random.choices(string.ascii_lowercase + string.digits, k=16))
salt = secrets.token_bytes(32)
sym_key = scrypt.hash(random_string, salt, N=2048, r=8, p=1, buflen=32)
```

## SECURITY VULNERABILITIES & RECOMMENDATIONS
============================================

### CRITICAL SECURITY ISSUES:
1. **Plain Text Password Storage**
   - Current: Passwords stored in plain text in passwd.csv
   - Risk: Complete credential exposure if file is compromised
   - Recommendation: Implement password hashing (bcrypt, Argon2, PBKDF2)

2. **Weak RSA Key Size**
   - Current: 1024-bit RSA keys
   - Risk: Vulnerable to advanced cryptographic attacks
   - Recommendation: Upgrade to 2048-bit or 4096-bit RSA keys

3. **HTTP Communication**
   - Current: Flask API runs on HTTP
   - Risk: Man-in-the-middle attacks, credential interception
   - Recommendation: Implement HTTPS/TLS encryption

4. **Session Storage**
   - Current: In-memory session storage
   - Risk: Sessions lost on server restart
   - Recommendation: Persistent session storage with expiration

### MEDIUM PRIORITY ISSUES:
1. **CSV File Security**
   - Recommendation: Encrypt CSV files at rest
   - Implement file integrity checking
   - Use database with proper access controls

2. **Error Handling**
   - Recommendation: Implement secure error messages
   - Avoid information leakage in error responses

3. **Input Validation**
   - Recommendation: Implement comprehensive input sanitization
   - Add transaction amount limits and validation
